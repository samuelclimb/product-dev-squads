# C4 model

C4 provides hierarchical views of system context, containers, components, and code, plus supporting dynamic and deployment views. Start with context and containers when they explain the change; add component detail only when needed. A diagram should show scope, named elements, responsibilities, and clearly labeled relationships.

Use the [official C4 diagrams guide](https://c4model.com/diagrams). Do not draw all levels by default or use a static structure diagram to stand in for a business process or state machine.
